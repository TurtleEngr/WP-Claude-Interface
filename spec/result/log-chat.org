*** `claude.php` — three additions

**`claude_chat_get_log_path( $log_subdir, $log_file )`** (new private helper)
Calls `wp_upload_dir()`, builds the path `basedir/$log_subdir/$log_file`, creates the subdirectory with `wp_mkdir_p()` if it doesn't exist, and returns the absolute path. The directory name (`'claude'`) and file name are plain variables — change them in one place.

**`claude_chat_log_message( $message, $response )`** (new)
Calls the helper with `$log_subdir = 'claude'` and `$log_file = 'claude_log.org'`, then appends an entry in the exact org-mode format you specified:
```
xx 2025-04-04 14:32 message
<user message>
xxx response
<claude response>
```

**`claude_chat_log_error( $error_type, $error_message )`** (replaced)
Now uses the same helper with `$log_file = 'claude.log'` instead of the old `plugin_dir_path()` approach. Error entries are structurally unchanged.

**`claude_chat_api_request()`** — one new line added after the successful API response branch:
```php
claude_chat_log_message( $message, $response_text );
```

---

*** `.htaccess` (plugin root)
Unchanged — still guards the legacy `claude-chat-error.log` in case it exists.

*** `uploads-claude-.htaccess` (new — deploy to `wp-content/uploads/claude/`)
Rename this to `.htaccess` and drop it into `wp-content/uploads/claude/`. It denies direct HTTP access to all `.log` and `.org` files in that directory, so neither `claude.log` nor `claude_log.org` is publicly readable even though they live under `uploads/`.
